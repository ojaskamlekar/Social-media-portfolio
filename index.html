WeCloud

A cloud storage usage metering and billing engine. I connected storage, bandwidth and API consumption to usage aggregation, pricing calculations and automated PDF invoices.

PythonFastAPIPostgreSQLRedisAWS EC2DockerGCS

From usage to an invoice

REST APIs and analytical queries support usage aggregation and billing workflows. PostgreSQL handles the data, with pricing calculations feeding automated PDF invoices.

Access and integrity

I integrated Google Cloud Storage and Redis, with authentication, role-based access control, validation and file integrity verification.

Deployment and visibility

I containerized the backend with Docker, deployed it on AWS EC2 and configured CloudWatch logs and monitoring. API load testing covered 1,000 requests with 10 concurrent users.

02 / The way I approach a problem

First, ask a
better question.

My starting points for a few situations. These are approaches I would take, not claims about client results.

Audience → Journey → Outcome

Find where the drop actually happens.

My first question is whether we’re reaching the right audience. I’d verify tracking, compare similar time periods, and break results down by audience, placement and creative. Then I’d look at click costs, conversion rate and qualified leads to see whether the issue is the ad, the page or what happens after the enquiry.

The question I’d ask: “Are we buying more attention, or more useful conversations?”
